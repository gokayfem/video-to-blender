# AGENTS.md

Guidance for coding agents working on Video2Nodes. Read this whole file before editing anything.

Video2Nodes turns an AI-generated reference video into an editable Blender node system (Geometry Nodes, Shader
Nodes, simulation zones where state is needed). The reference is the visual specification; the graph is the
editable explanation we build for it. First example: **Storybook Street**, a curve-driven street generator rebuilt
from `reference/source/village_source.mp4` (AI-generated, 20.04 s, 481 frames, 1280x704, 24 fps).

Sibling project: `/Users/gokay/shader-skills` (Video2GLSL). Read-only from here. Its
`prompts/village-loop/REFERENCE.md` is a measured breakdown of the same clip and its `src/*.glsl` implement the
same street as SDFs; mine them for proportions, palette and motion, translate into nodes, never paste GLSL.

## Layout

```text
v2n/graph.py            Graph builder: node(), group(), input()/output() with panels, math shorthands,
                        frame() context, auto-layout. ALL node trees are built through it.
v2n/inspect.py          dump_groups() to JSON, check_groups() lint, modifier inputs by name, evaluated_stats()
street/groups/frame.py  SS Street Point: (s, d, h) street space -> world Position + Rotation (shared, lead-owned)
street/groups/*.py      one module per node group family, each exposing build() -> its top node group
street/materials/*.py   one module per owner; common.py has material() and flat()
street/scene.py         path curves (reference, straight, s_bend, hill, spiral), sun/world, camera, render setup
street/build.py         builds the full .blend (lead-owned)
tools/try_group.py      build ONE group in a test scene, print stats/warnings/lint, render a PNG, save a .blend
reference/              source clip (not in git), frames, contact sheets
docs/                   REFERENCE, GRAPH, CONTROLS, PRIOR_WORK, TRANSFER, COMPARE
out/<owner>/            scratch renders per owner (not in git)
```

## Units and street space

- **1 unit = H = the walker's full height.** All reference measurements are in H.
- Street space is (s, d, h): arc length along the path curve, lateral offset (+ = left of travel), height above
  the curve. Place everything through `SS Street Point` (`street/groups/frame.py`): it returns world Position
  and a Rotation whose +X runs along the street, +Y points left, +Z up. Model parts in street space, instance
  them with that rotation; the effect then follows any curve, including hills (Z) and tight bends.
- Cross-section (defaults, all exposed): Street Width 4.0 (curb to curb), Curb Width 0.2, Curb Height 0.12,
  Verge Width 0.8. Facade line at |d| = Street Width/2 + Curb Width + Verge Width = 3.0.
- The walker travels s(t) = Walk Start + Walk Speed * t, Walk Speed 0.9 H/s, t = seconds.

## Group contract

Every top group a module builds:
- is named `SS <Name>` and has a `description`; every input has a `description` (check_groups enforces this);
- uses these exact shared input names where relevant: `Curve` (GEOMETRY, path), `Time` (FLOAT seconds; never
  read Scene Time inside a group, so graphs are testable and retimable), `Seed` (INT), `Street Width`,
  `Curb Width`, `Curb Height`, `Verge Width`;
- groups other inputs into panels named for what an artist thinks about ("Houses", "Timber", "Windows",
  "Palette", "Wind"), with min/max and subtype set; expose the few controls that change the look meaningfully,
  not every constant;
- outputs `Geometry` (plus extra named outputs only where this file defines them);
- organises internals with `g.frame("What this block does")`, and splits reusable pieces into sub-groups
  (`SS <Name> <Part>`), so the graph reads as an explanation;
- produces zero node warnings and zero `check_groups` problems on all five test paths.

Materials: named `SS <Material>`, built in `street/materials/<owner>.py` with Shader Nodes (procedural textures;
image textures only if documented and justified). Per-piece variation comes from named attributes written in
Geometry Nodes and read by an Attribute node (type GEOMETRY): `ss_color` (FLOAT_COLOR, the piece's base tint) and
`ss_rand` (FLOAT 0..1). The assembly realizes instances once at the end, so instance attributes reach the
material through realize; read them with Attribute type GEOMETRY.

### Facades -> Props interface (`Anchors`)

`SS Facades` has a second output `Anchors`: a point cloud (mesh vertices) on the facade surfaces with
- `anchor` INT: 1 ground-floor window sill, 2 upper window sill, 3 door base (centre), 4 shopfront top
  (awning line), 5 wall-lantern spot beside a door, 6 hanging-sign bracket spot, 7 verge spot (ground against the
  wall base, for pots and barrels);
- `ss_rot` (ROTATION): +X along the wall, +Y out of the wall toward the street centre, +Z up;
- `ss_width` FLOAT (opening width; for verge spots, free length along the wall), `ss_house` INT, `ss_rand` FLOAT.
`SS Props` takes `Anchors` (GEOMETRY) and places window boxes, pots, barrels, awnings, signs and lanterns there.
Until facades land, props tests with its own mock anchors (`test_inputs` in its module).

## Verifying your group

```bash
cd /Users/gokay/Video2Nodes
blender -b --factory-startup --python tools/try_group.py -- --module street.groups.road --png out/road/t.png
blender -b --factory-startup --python tools/try_group.py -- --module street.groups.road --path spiral \
    --cam 0,0,30:0,0,0 --png out/road/spiral.png --save out/road/road.blend
```

Look at every PNG you produce (Read the image). Compare against `reference/frames/tNN.png` (one per second).
Check all five paths (reference, straight, s_bend, hill, spiral). For animated groups render several frames and
judge them as a sequence. Keep test renders small (640 px, 8 samples): up to eight agents share this machine.

## Quality bar

"I imagined that animation, and now I have the procedural tool that makes it." Match the reference's shapes,
proportions, palette and motion closely, and keep the graph something an artist can read and change. Report
visual differences honestly; never invent accuracy numbers.
